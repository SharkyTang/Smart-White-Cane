## 2. 准备好这几样东西

- Mac 和 iPhone 16 Pro Max；本工程最低要求 iOS 18。
- 能传数据的 USB-C 线，不能只有充电功能。
- 你自己的 Apple 账户；密码和验证码只在 Apple/Xcode 系统界面输入，不要发给别人。
- Mac 和 iPhone 接入同一个可信 Wi-Fi，测试期间保持 Mac 唤醒。
- 正式验收还需要三脚架、卷尺、椅子或静止人员，以及一位协助者。

手机负责采集、显示和说话，Mac 负责 YOLO 检测，所以**只运行 Xcode 中的 App 还不够，Mac 上也必须启动检测服务**。

不需要为了本地装到自己的手机上测试而先购买付费开发者会员；Xcode 的个人团队 `Personal Team` 可用于个人设备测试，但有免费签名期限等限制，过期后可能要重新运行安装。上架 App Store 是另一件事。[Apple：会员与个人设备测试](https://developer.apple.com/support/compare-memberships/)

## 3. 在 Xcode 登录 Apple 账户

1. 在 Mac 屏幕最上方菜单栏，点击 **Xcode → Settings…（设置）**，快捷键是 `Command + ,`。
2. 找到 **Apple Accounts**；某些版本显示为 **Accounts（账户）**。
3. 点击添加账户按钮（可能是 `+` 或 `Add Apple Account`），登录你自己的 Apple 账户，按提示完成双重认证。
4. 确认列表中出现自己的账户，再关闭设置窗口。

这一步只是让 Xcode 知道用谁的身份给测试 App 签名，不会把项目自动发布到 App Store。[Apple：当前账户与签名设置](https://developer.apple.com/documentation/xcode/running-your-app-on-simulated-or-physical-devices)、[Apple：旧版账户添加说明](https://help.apple.com/xcode/mac/current/en.lproj/devaf282080a.html)

## 4. 连接 iPhone，并开启开发者模式

1. 用数据线连接 Mac 和 iPhone，解锁手机，暂时不要锁屏。
2. 如果 Mac 询问是否允许配件连接，选择允许；iPhone 如果显示“要信任此电脑吗？”，选择**信任**并输入手机锁屏密码。
3. 在 Xcode 顶部菜单打开 **Window → Devices and Simulators（设备与模拟器）**，也可按 `Command + Shift + 2`。较新界面可能改称 **Device Hub**，或从运行设备选择器里的 **Manage Devices** 进入；找设备管理页面即可。
4. 在 **Devices（设备）**页找自己的 iPhone；新版可在侧栏筛选 **Physical Devices（物理设备）**。看到手机后继续下一步。如果提示 `Developer Mode Disabled`，不必一直等“准备完成”，需要先开启开发者模式。
5. 在 iPhone 打开 **设置 → 隐私与安全性 → 开发者模式（Developer Mode）**，打开开关。
6. 按手机提示重启；重启解锁后，再确认**开启**开发者模式，并输入锁屏密码。随后回到 Xcode，等待剩余的设备准备工作完成，首次可能需要几分钟。

若手机里没有“开发者模式”：先完成数据线连接、信任和 Xcode 配对，再回到设置查看。若 Xcode 完全找不到手机，先换数据线/接口，不要通过新建工程来解决。

“信任此电脑”和“开发者模式”是两步，都不是后面 HTTPS 的证书信任。[Apple：信任电脑](https://support.apple.com/zh-cn/109054)、[Apple：开启开发者模式](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device)

## 6. 把 App 安装到真正的 iPhone 上

1. 在 Xcode 顶部工具栏找到方案 **SmartCaneLiDAR** 和旁边的运行设备选择器。
2. 选择刚才连接的**真实 iPhone 名称**。不要选择 `Any iOS Device` 这类通用目标，也不要选择带 `Simulator` 的模拟器。
3. 点击顶部的 **▶ Run（运行）**，或按 `Command + R`。
4. 等待编译、安装。若提示解锁手机，就在手机上解锁；若要求访问钥匙串，先确认请求来自 Xcode/签名工具，再按系统提示授权。
5. 正常结果：手机出现 App，打开后标题为 **LiDAR 导盲验证**。

第一次可能较慢。`Build Succeeded` 只表示构建成功，还要确认手机上的 App 确实启动了。若手机提示开发者不受信任，按照提示到“设置 → 通用 → VPN 与设备管理”检查并信任**你自己的开发者身份**；如果没有这类提示，不用主动寻找或安装别人的描述文件。

模拟器可以验证界面/部分逻辑，**没有真实 LiDAR，不能用于本次测距验收**。如果真实设备显示系统版本不受当前 Xcode 支持，应按 Xcode 提示安装相应平台支持或使用支持该系统的 Xcode；不用为了真机 LiDAR 测试先安装一大套模拟器。[Apple：选择运行目标](https://developer.apple.com/documentation/xcode/running-your-app-on-simulated-or-physical-devices)

## 7. 启动 Mac 服务，让手机连得上

### 7.1 在 Mac 打开终端

按 `Command + 空格`，搜索“终端”，打开系统的 Terminal。下面的命令是在 **Mac 终端**运行，不是粘贴到 Xcode 的代码编辑器或底部调试区。

先进入项目目录：

```bash
cd "/Users/shaoqitang/Documents/ChatGPT/智能导盲杖"
```

第一次配置环境，或提示依赖缺失时，运行：

```bash
uv sync --dev
```

如果显示 `command not found: uv`，先停在这里，把提示发给项目维护者处理环境，不要下载来历不明的安装脚本。

### 7.2 生成本地 HTTPS 证书

如果此前 Safari 验证已在这台手机安装并信任了本项目 CA，且 Mac IP 未变、证书仍有效，可以复用，不必重复安装。

首次使用、Mac 换了 IP 或服务器证书过期时，运行：

```bash
scripts/create_mobile_cert.sh
```

脚本会显示“手机访问地址”，例如 `https://192.168.1.8:8443`。**例子里的 IP 不是你的固定地址，请用终端实际显示的值。** 脚本自动识别失败时，到 Mac“系统设置 → Wi-Fi → 当前网络的详细信息 → TCP/IP”查看 IP，再运行 `scripts/create_mobile_cert.sh 实际IP`。

脚本会复用现有 CA，更新服务器证书；不要为了重试随意删除原 CA。若服务已经运行，更新证书后需要停止服务再启动，才会使用新证书。

### 7.3 在 iPhone 安装并信任本项目 CA

1. 在 Mac 打开 Finder，按 `Command + Shift + G`，进入：

   ```text
   /Users/shaoqitang/Documents/ChatGPT/智能导盲杖/.mobile-certs
   ```

2. 找到 **mobile-ca.cer**，右键 → 共享 → 隔空投送，发送到自己的 iPhone。
3. 在手机接受；按照提示，到“设置 → 已下载描述文件”安装。如果顶部没有该入口，查看“设置 → 通用 → VPN 与设备管理”。确认名称为 **Smart Cane Local Test CA**。
4. 安装后，再打开 **设置 → 通用 → 关于本机 → 证书信任设置**，为 **Smart Cane Local Test CA** 启用完全信任，并确认提示。

只安装你自己刚生成的证书；**只传 `.cer`，绝不能把 `.key` 私钥文件发出去**。安装证书与“启用完全信任”是两步，少后一步 App 仍可能无法连接。测试结束不再使用时，可在“VPN 与设备管理”移除此测试描述文件。[Apple：手动信任证书](https://support.apple.com/zh-cn/102390)、[Apple：安装描述文件](https://support.apple.com/zh-cn/102400)

### 7.4 启动服务并检查网络

回到 Mac 终端，在项目目录运行：

```bash
uv run smart-cane-mobile
```

保留这个终端窗口运行。第一次检测可能需要下载模型并初始化，准备完成后再开始计时。按 `Control + C` 才会停止服务。

找到终端里以 `iPhone client:` 开头的 HTTPS 地址。不要把 `localhost`、`127.0.0.1` 或 `0.0.0.0` 填进手机，那不是手机可访问的 Mac 局域网地址。多个地址时，选同一 Wi-Fi 下且已写入证书的那个 IP。

在手机 Safari 打开“实际服务地址 + `/healthz`”，例如 `https://192.168.1.8:8443/healthz`。成功时看到：

```json
{"status": "ok"}
```

这一步只检查 HTTPS 服务能否访问，**不代表 YOLO 和 LiDAR 已工作**。证书有警告时先修复，不要靠“继续访问”代替完整信任。也不要在 Safari 同时点“开始检测”；原生 App 测试期间只保留一个检测客户端，避免相互重置会话。

### 7.5 在 App 做第一次跑通检查

1. 回到手机上的 **LiDAR 导盲验证**，向下滚动找到 **Mac 检测服务**。
2. 把输入框中的示例 `https://192.168.1.2:8443` 改成你终端实际显示的地址，**App 中不要加 `/healthz`**。
3. 点击 **声音测试**，应听到“声音测试正常”。这只验证发声，不验证测距。
4. 先保持 **受控验证日志 → 记录元数据 JSONL** 关闭。
5. 手机竖直固定，让椅子或静止人员处于画面中央、约 1.5 米处。
6. 点击 **开始检测**，出现相机、本地网络授权时选择允许；本项目不需要录音权限。
7. 等待状态变为 **LiDAR + YOLO 检测中**，观察画面和数据。

第一次跑通需要确认：

- [ ] 相机画面方向正确；黑边可以存在，图像不应被拉伸或左右镜像。
- [ ] 出现与目标对应的框，“稳定目标”数量大于 0。
- [ ] 目标在中央时，“前向距离”出现米数，“深度质量”能看到有效状态。
- [ ] 约 1.5 米的有效距离经过稳定确认后进入中风险，并听到包含类别、方向和约数的提醒。
- [ ] 点“停止”后不再继续检测/播报旧提醒。

如果画面中没有 YOLO 识别框，LiDAR 不会凭空生成目标。先试椅子或静止人员；纸箱、细杆、玻璃不保证会被当前模型识别。未检出要记为“识别限制”，不能伪装成测距通过。

完成这些，只能勾选“链路跑通”，不能勾选“正式验收通过”。

## 8. 正式测距：怎么摆、怎么填、测多久？

### 8.1 固定测量条件

- 受控、明亮的室内，手机竖屏固定在三脚架，测试者不依赖 App 行走。
- 卷尺起点为后置相机所在平面，终点为目标最近可见表面，不从三脚架底座起量。
- 比较的是前向深度；边缘位置测试不要把随意的斜线距离当成同一前向真值。
- 静态误差测量时尽量只让一个待测目标进入识别框，避免把一个卷尺真值套给多个远近不同的目标。
- 同一场景记录手机/iOS、Mac/macOS、Wi-Fi、目标、材质、位置、真值和 App 版本。
- 先让模型和画面稳定，再记录；别把下载模型或初始授权耗时混进常规性能样本。

### 8.2 App 验证模式填写示例

展开 **受控验证日志**。以“椅子、中央、1.5 米、第 1 轮”为例：

| App 里的项目 | 填什么 / 怎么选 |
|---|---|
| 记录元数据 JSONL | 准备时关闭，正式采样时开启 |
| 调试 A/B：使用 smoothedSceneDepth | 正式验收保持关闭，使用 `raw_scene_depth` |
| 场景编号 | `chair-center-1p5m` |
| 本轮编号 | `run-1`；之后分别用 `run-2`、`run-3` |
| 卷尺真值（米，可选） | `1.5`，只填数字，不加“米” |
| 材质分组 | 普通椅子选“普通不透明”；玻璃等选“边界材质” |
| 本场景预期应播报 | 纯静态误差采样先关闭；脚本化提醒测试见第 9 节 |
| 预期事件编号 | 静态误差采样可留空 |
| 更新记录条件 | 修改场景/轮次/真值等后点一次，确保实际日志使用新条件 |

开启记录后，调试距离会显示到 `0.01m`；这只是显示精度，**不代表测量误差只有 1 厘米**。正常显示为 `0.1m`。

### 8.3 每个组合至少三轮

一个“组合”是固定的目标、位置、距离和材质，例如 `chair-center-1p5m`。

1. 保持记录关闭，摆好目标，输入本轮条件，点击“更新记录条件”。
2. 等目标稳定后打开“记录元数据 JSONL”，保持目标不动，先录约 10～15 秒。
3. 关闭记录，调整目标后重新摆回同一测量位置；把轮次改为 `run-2`，再点“更新记录条件”。
4. 稳定后再次打开记录；同样完成 `run-3`。
5. 每轮最终必须在报告中确认至少 **30 个稳定帧**。不是 30 秒，也不是随便 30 张画面；录够时长并不保证稳定帧够数，不够就补测。

每个目标/距离组合都要各做三轮，不是整个项目一共三轮。同一组合三轮保持场景编号一致；换距离、位置或材质就换场景编号。

日志暂停期间的空白时段可能影响当前分析脚本的整段处理频率统计。**精度分段采样与连续性能测试分开导出、分开分析**；不要拿含摆放等待时间的长日志判断 8 Hz 是否达标。连续性能测试中不切换记录开关。

### 8.4 需要覆盖的目标和距离

| 分组 | 目标 | 距离点 | 每个组合 |
|---|---|---|---|
| 普通不透明 | 纸箱、椅子、静止人员；只对实际正确出框的目标测距 | 0.5、1.0、1.5、2.0、3.0、4.0、5.0 米 | ≥3 轮，每轮 ≥30 稳定帧 |
| 边界材质/形状 | 细杆、深色布、玻璃、镜面 | 同上；无法出框或深度无效也要单列记录 | ≥3 次尝试，不得隐藏失败 |
| 配准检查 | 选已稳定识别的不透明目标 | 代表性距离下：左、中、右、左上、右上、左下、右下 | 检查框与同一物体表面是否一致，并记录距离 |

普通目标 **0.5～4 米**是主要误差门槛范围；5 米是边界诊断点，因为算法会丢弃超过 5 米的深度。玻璃、镜面等结果单列，不能用普通目标的好成绩抵消。

纸箱等未被检出的场景没有有效的“框内距离”样本，要在结果中写明未检出和尝试次数。日志覆盖率衡量的是已有稳定目标上的有效距离，不代表所有障碍物的检出率。

## 9. 验证风险、播报和异常恢复

### 9.1 看懂画面里的词

| 显示/日志内容 | 中文含义 |
|---|---|
| `lidar` | 当前风险采用有效的 LiDAR 米数 |
| `area_fallback` | 深度不可用，临时按框面积判断；提醒不允许带米数 |
| `valid` | 当前有效距离 |
| `stale` | 历史距离已过时，不能当当前测量值 |
| `unavailable` | 当前无可靠距离 |
| `raw_scene_depth` | 正式验证使用的原始深度 |
| 覆盖比例、样本数 | 单个框内的深度质量；要求至少 12 个合格像素且覆盖率 ≥20% |
| 前向距离 | 中央方向目标的距离；目标都在侧边时可能显示不可用，不一定是故障 |

单框“20% 深度像素覆盖率”和整批验收“90% 有效距离覆盖率”不是同一个指标。

### 9.2 默认风险与确认规则

| 新鲜有效距离 | 默认风险 |
|---|---|
| ≤1.0 米 | 高 |
| >1.0 且 ≤2.0 米 | 中 |
| >2.0 米 | 低 |

距离经过框内取样和最近 3 个有效值的中位数平滑。风险升级要连续 2 个新鲜距离样本确认，降级要连续 3 个样本，并分别越过 1.15 米或 2.15 米的退出阈值。因此在边界附近不应每帧变色；“立即播报”是**风险/方向确认变化后不再等 3 秒冷却**，不代表完全没有确认延迟。

同类别、方向、风险的相同提醒遵守 3 秒冷却；0.1 米的抖动不应单独触发新提醒。语音在 2 米内按 0.1 米、2 米以上按 0.5 米表达。深度无效时只能做不含米数的通用提醒。

### 9.3 按事件测试，不要整段随意勾“预期应播报”

在目标进入预期触发条件**之前**，开启“本场景预期应播报”，填写唯一事件编号，并点击“更新记录条件”。例如：场景 `person-cross-1m`，轮次 `run-1`，事件 `run1-enter-high-01`。

发生该事件、完成观察后，关闭“本场景预期应播报”并更新条件；下一次用新的事件编号。动态目标、双目标不要填写一个固定卷尺真值，避免被误算成静态误差。

| 测试 | 操作 | 应看到/听到 |
|---|---|---|
| 进入中风险 | 手机不动，助手将已识别目标从 >2 米移到约 1.8 米 | 确认后中风险提醒 |
| 中升高 | 从约 1.5 米移到约 0.8 米 | 确认后高风险，立即发出“危险……”提醒 |
| 降级迟滞 | 从近处移回 >1.15 米、再 >2.15 米并保持 | 连续确认后降级，不在 1/2 米附近来回跳 |
| 方向变化 | 维持大致前向距离，让目标依次处于左、中、右 | 方向更新，变化后提醒不被原冷却挡住 |
| 冷却 | 同一目标、方向、风险连续保持至少 10 秒 | 同类重复提醒间隔 ≥3 秒，不因小幅米数抖动刷屏 |
| 多目标优先级 | 两个目标，分别改变风险、方向、距离 | 先高风险；同风险先前方、再较近，再比较框面积/置信度 |
| 高风险抢占 | 较低风险提醒尚未结束时出现高风险事件 | 高风险可打断较低风险语音 |
| 无效深度 | 对已被正确识别的边界目标观察低置信/无效深度 | 显式不可用/降级，不播精确米数；没复现就写“未测” |

每个正式脚本化场景至少重复 3 轮；不要只因某轮听到一句话就判定全部事件都成功。记录预期事件的数量及实际响应。

### 9.4 异常和连续运行

先导出当前测距日志，再做这些会中断会话的测试：

- [ ] Wi-Fi 断开再恢复：显示断线/重连，重置会话，没有旧画面/旧提醒集中重放。
- [ ] 切到后台再回来、锁屏再解锁：后台停止发送，回来后用新会话恢复。
- [ ] 拒绝相机权限：能明确失败而不是卡死；恢复权限后可以重新开始。
- [ ] 拒绝本地网络权限：连接失败可理解，恢复权限后可以重连。
- [ ] ARKit 中断：中断时停止采集，恢复后重置会话；无可控复现条件时写“未测”。
- [ ] 热状态：`serious` 时目标频率降到 5 Hz，`critical` 时停止采集。不可用加热、包裹等方式强行让手机过热；未自然出现就写“真机未测”，自动化覆盖不能冒充真机通过。
- [ ] 正常热状态连续运行 5 分钟：不切后台，不暂停日志；无崩溃、旧提醒重放，也不保存 RGB/深度画面。

正常热状态的性能目标是 ≥8 Hz；热保护时主动降为 5 Hz 的记录要单列，不混入正常性能结果。严禁边走边试、上道路、楼梯或坑洞旁测试。

## 10. 导出 JSONL，并生成分析报告

### 10.1 从手机导出

1. 完成本次会话的采样，先等最后一句提醒完成，再点击 **停止**。
2. 在“受控验证日志”点击 **准备导出**；出现 **导出** 后点击。
3. 在系统分享面板中选择隔空投送到 Mac，或者存储到你指定的位置。
4. Mac 上确认收到 `validation-某个会话编号.jsonl` 文件，并记录它属于哪些场景/轮次。

JSONL 是“一行一个记录”的文本日志，不是视频。当前 App 不会在里面保存 RGB、深度像素或音频，但会记录距离、风险、耗时以及播报文案等元数据。

**每次重新开始、断网重连或后台恢复都可能创建新会话文件。导出按钮只指向当前日志，不是历史日志列表。** 最稳妥的是“停止 → 准备导出 → 确认 Mac 收到 → 再开始下一次”。断网/后台测试前先备份前一段；需要恢复旧日志时不要卸载 App，把当前情况交给维护者处理。

### 10.2 在 Mac 生成报告

在项目目录的终端运行下面命令，把输入路径替换成实际导出文件路径；可以先输入命令，再把文件从 Finder 拖到终端取得路径：

```bash
cd "/Users/shaoqitang/Documents/ChatGPT/智能导盲杖"
uv run python scripts/analyze_lidar_validation.py \
  "/实际保存位置/validation-会话编号.jsonl" \
  --output docs/milestone-0.4-lidar-results-run-1.md
```

多个会话属于同一批采样时，可以在 `--output` 前依次列出文件：

```bash
uv run python scripts/analyze_lidar_validation.py \
  "/实际保存位置/validation-会话A.jsonl" \
  "/实际保存位置/validation-会话B.jsonl" \
  --output docs/milestone-0.4-lidar-results-batch-1.md
```

每个文件只传一次，按采集顺序列出；不要同时传同一日志的多个重复副本。`--output` 同名文件会被覆盖，保留旧报告时换一个批次文件名。暂时不熟悉终端的话，也可以把导出的 JSONL 交给维护者分析；不要为了方便附带现场照片。

### 10.3 报告仍有英文，怎么看？

当前分析脚本的报告表头是英文；本次新增的是中文操作手册，没有修改分析程序。

| 报告词语 | 中文解释 |
|---|---|
| `PASS` / `FAIL` | 该项通过 / 不通过 |
| `INCOMPLETE` / `NOT MEASURED` | 数据不完整 / 该项未测；都不能当通过 |
| `Metadata gates` | 元数据能够检查的门槛，不是最终真机验收结论 |
| `Median absolute error` / `P95 absolute error` | 绝对误差中位数 / 95% 样本不超过的误差 |
| `Valid LiDAR coverage` | 有稳定目标时，获得有效 LiDAR 距离的比例 |
| `Frame ID mismatches` / `Replayed/out-of-order frames` | 帧号不匹配 / 重放或乱序 |
| `P95 round trip` / `Effective processing rate` | 单帧往返耗时 P95 / 有效处理频率 |
| `P95 speech start` / `P95 high-risk speech start` | 普通/高风险语音开始延迟 P95 |
| `Cooldown violations` / `Invalid numeric speeches` | 冷却违规 / 无效深度却播米数 |
| `Expected alert misses` / `Expected alerts without event ID` | 预期事件漏播 / 没填事件编号 |
| `Runs below 30 stable samples` / `Scenarios below three runs` | 稳定帧不足 30 的轮次 / 不足三轮的场景 |
| `Failing required scenarios` | 必测普通目标场景中的不合格项，不能被总平均掩盖 |

只测一把椅子的静态误差，报告可能因未测高风险语音等项目显示 `INCOMPLETE`，这不等于程序故障。异常测试中没有有效目标的记录也可能无法满足稳定帧门槛，应单列说明，不能删掉失败后声称全通过。

语音日志使用 `AVSpeechSynthesizer.didStart` 回调；当前计时从关联提醒帧的采集时间到这个回调，不是麦克风测得的实际声波起点，也不包含目标在更早帧尚未被确认的时间。需要同时人工核对“从目标进入条件到实际听到”的体验，不能仅靠一个数字证明完整感知延迟。

即使报告全部 `PASS`，配准、材质限制、权限/恢复、五分钟运行和不落盘仍要人工完成。也要核对完整场景矩阵，脚本不会凭空知道你漏测了哪一种目标。

## 12. 什么情况下可以说“有效”？

- 全部门槛及人工清单完成且通过：只能说“在受控室内、已被 YOLO 识别的目标上，框 + LiDAR 米数 + 播报策略在本次测试范围内有效”。
- 仅部分材质/距离通过：写清目标和距离范围；失败场景不允许继续精确报米数。在采取限制/修正前，不得泛化结论。
- 配准、测距误差、延迟或无效深度错误报米数任一关键项失败：停止进入行走测试，先修复再复测。
- 尚有关键项目未测：结论是“未完成”，不是“默认通过”。

即使全通过，也不证明漏检障碍、玻璃/镜面、楼梯/坑洞等负障碍或真实道路导航安全。本轮不涉及 Core ML 迁移、GPS、SLAM、触觉或独立导航。
