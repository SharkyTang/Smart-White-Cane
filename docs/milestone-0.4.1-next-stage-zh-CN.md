# 下一阶段建议：0.4.1 稳定性修正与 YOLO26n 重新验收

状态：YOLO26n 已设为默认检测模型；稳定性修正和真机重新验收仍待完成。依据为用户提供的run-1/2/3和现场误识别说明。

## 当前结论

1.5米椅子三轮采集已齐：693个有效距离，合并中位绝对误差2.54厘米，P95为5.27厘米。仅此目标/距离的测距指标满足计划；不代表全项LiDAR验收完成。

三轮均出现播报等待，最长分别3.86、4.02、7.17秒。开口前最新记录显示距离失效或目标消失的数值提醒有2条。这里的“最新记录”不是开口瞬间的深度重采样。

此前三轮使用YOLO11n，结果只作为历史记录；当前默认已经切换为YOLO26n，后续直接重新验收，不要求再跑YOLO11n对照。中文名称映射只有19类，tv/bed/toilet/microwave等会被说成“障碍物”。这是文案映射缺失，与椅子错认马桶、猫错认狗的模型分类问题不同。更新通用预训练模型也不等于能识别任意障碍。

## 第一阶段：0.4.1 修正当前链路（优先）

### P0 播报队列、过时提醒、ACK一致性

- 为待播提醒设置有效期；只保留当前仍相关的候选，不积压历史语音。
- 播放前检查最新session、track、方向、风险和深度新鲜度；失效就更新、降级或取消，禁止旧米数继续播。
- 高风险要能优先于整个等待队列，不只判断正在播的一句。
- 保留alert_id去重、成功开始后ACK、重复ACK幂等；过期/取消提醒不能被服务端反复重新排队。
- 增加队列、抢占、目标消失、深度失效、断网和会话重置的自动化测试。

### P1 风险回退与重复分类

- YOLO漏检时保留的旧大框不能被当成新的可靠高风险证据。
- 当前有视觉目标但没有可靠深度时，仍提供适当通用提醒，不报米数；不能因标签不确定而静默掉真实障碍。
- 检查深度初始化/失效时面积与米制风险的切换，避免静止1.5米目标突然“危险→低风险→注意”。
- 对同物体多类别框做时序与空间冲突处理；不能全局屏蔽tv/toilet，也不能简单删掉全部重叠框，需保留真实相邻目标。
- 类别不稳定时保守命名；LiDAR深度可信不等于物体名称可信。

### P1 中文类别与观测信息

- 补全当前COCO 80类中文映射，iOS/Safari保持一致并加覆盖测试。
- 调试界面区分原始类别、中文名称、模型置信度、深度质量和回退原因。
- 元数据增加模型/权重指纹、推理参数、bbox/置信度、入队/开口/取消时间、最新证据状态、预期事件编号；默认仍不保存RGB/depth。
- 修复分析器的原始frame关联、多目标真值绑定和可选距离字段口径。

### 退出条件

- 单元/集成测试覆盖旧提醒取消、队列抢占、ACK重试、类别映射及风险来源切换。
- 修正版本受控复测中，过时米数播报为0；已标注中高风险事件漏播为0。
- 普通确认到开口P95≤800ms；真正≤1米的新鲜LiDAR快速确认事件≤500ms，不能用面积回退事件代替。
- 相同提醒遵守3秒冷却，升级/方向变化按规则处理；原1.5米椅子精度不退化。

## 第二阶段：0.4.2 YOLO26n 复测

- 直接使用YOLO26n，不再安排YOLO11n或YOLO11s的新测试；旧JSONL仅用于了解历史问题。
- 保持输入尺寸640、置信度0.45、硬件、推理设备和输入流程不变，避免把其他参数变化误认为模型改善。
- 正式连接iPhone前先在Mac下载并完成一次YOLO26n冷启动烟测，避免首次下载让手机请求超时。
- 用户主动选择并提供可复现的错误框截图/测试素材，包括椅子与头枕、真实电视/马桶、猫狗、不同角度/背景；不自动录像或上传云端。
- 将调参集与留出测试集按场景/拍摄片段分离，避免相邻视频帧分到两边。几张错例只做复现，不作为充分训练数据。
- 评估分类混淆、漏检、错误提醒次数、测距ROI、往返P95、有效Hz和热状态。当前三轮7.09–7.87Hz尚未达到8Hz，不只看准确率。
- 新JSONL会记录`model_name=yolo26n.pt`，便于确认每轮实际使用的模型。
- 若YOLO26n仍持续误分类，先收集足够标注数据再评估微调；换新版不保证自动解决特定现场错例。
- 官方资料：[YOLO26](https://docs.ultralytics.com/models/yolo26/)、[COCO类别](https://docs.ultralytics.com/datasets/detect/coco/)。

## 第三阶段：YOLO26n 正式室内验收

先重做1.5米椅子三轮，再扩到0.5、1、2、3、4、5米和更多普通不透明目标，随后做左右/四角配准、跨阈值、双目标、断网/后台/权限/热保护及5分钟连续测试。

纸箱不在COCO独立类别清单中，不要求通用模型必然正确命名；只有正确出框时才纳入当前融合验证，未出框要记为能力缺口，不能被排除后宣称所有障碍安全。玻璃、镜面、细杆等边界目标单列。

关键误差、配准、延迟或错误米数任一门槛失败，继续停留在受控静态测试。不进入行走、道路、楼梯或坑洞试验，也不把App作为独立导航保障。

## 用户现在需要做的事
